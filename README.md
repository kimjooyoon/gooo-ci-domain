# Gooo CI domain

A small Go tool that treats verification work as a Gooo metaprogramming domain: source changes, their consumers, required checks, resource capacity, observed costs and a deadline. [한국어 설명](README.ko.md) · [domain analysis](docs/domain.md) · [observation origins](observations/README.md).

A one-line change can reach many packages. The plan follows those relationships and retains the resulting test obligations. The source-owned policy in [policy.gooo](policy.gooo) decides admission, cost reserve, first-seen cost discovery and the next action. Its six functions were projected with the [Gooo compiler](https://github.com/kimjooyoon/meta-ontology-go); generated byte hashes and source origins are retained in [origins](origins/policy-projections.json).

## What runs today

- Run an exact command with its source revision, tracked active files, executable digest and original scope clock. Stream its complete output while retaining a digest and byte count.
- Read exact clean Git revisions and host-module Go package metadata, including test imports and embed inputs.
- Derive reverse impact and test prerequisites. An input without an observed owner reaches every package through one shared input-domain node.
- Forecast the selected DAG using matching command/environment/resource observations. Show unknown costs explicitly.
- Report serial work, critical path and worker-capacity lower bounds under the estimated costs.
- Execute each required package once, with a common deadline and process-group cancellation covering child compilers.
- Observe Go testing's `os` input log, tying reads of `.gooo` fixtures to their consuming package.
- Persist a start origin before execution and append bounded cost origins afterwards. The package planner reserves its source cohort; the `work` adapter distinguishes current run/attempt identity from reusable historical command costs.

The current collector covers **host-module tracked-source Go-test obligations**. Compiler canonical checks, workflow orchestration, external services and other target architectures have their own obligations. The existing compiler CI remains separate. Runtime read observations are a bounded description of the Go testing `os` hook; subprocess and direct-syscall inputs require additional origins before they can support finer selection.

## Use

Requires Go 1.27.3 on Linux or macOS. The module uses the standard library.

```sh
go install github.com/kimjooyoon/gooo-ci-domain/cmd/gooo-ci-domain@latest

# Observe scope and forecast. No tests execute.
gooo-ci-domain plan --root /path/to/repository --base BASE_COMMIT

# First-seen source: bounded cost discovery of the full required population.
# Next functional source: forecast using prior origins, then verify the same population.
gooo-ci-domain improve --root /path/to/repository --base BASE_COMMIT

# Require a forecast before execution.
gooo-ci-domain check --root /path/to/repository --base BASE_COMMIT
```

The default total ceiling is 180,000 ms. `--budget-ms` declares an explicit ceiling for the current domain request. `--workers` selects available capacity and participates in the timing profile; costs from a different capacity have distinct keys. `--started-at` binds commands to one scope clock. The [workflow](.github/workflows/ci.yml) records the original run and starts its work scope at the first runner step, before checkout and setup. An input snapshot retains its scope start instead of resetting it on reuse.

Origins default to an external system cache, outside the source checkout. A custom journal uses `--journal`. Limits are 4 MiB, 4,096 records and 256 observations per cost context. A full journal produces an explicit error; it is never silently truncated. Unit output and read-origin populations are also bounded. No model weights or token-generation service are required.

For a multi-job workflow, [the runner clock](docs/runner-clock.md) derives one bounded allowance across runner-free gaps while preserving the original wall time.

For existing workflow commands, use the [source-bound `work` adapter](docs/command-origins.md). Each command keeps the same original scope clock and supplies an execution origin. Pass a run/attempt as `--execution-id` when a workflow may verify the same source again: prior costs can inform its forecast, while only this execution's outcome verifies the current run. Repeating a command within one execution is refused.

## Self improvement

The first source can return `VERIFIED_DISCOVERY`: its complete current check population actually passed within the controlled scope, while its pre-execution forecast was unavailable. The next functional source can return `VERIFIED_SCOPED` with empirical cost inputs. A timeout remains a censored observation and unresolved obligations remain visible. Cost origins improve the next forecast; current execution supplies current verification.

`COST_UNRESOLVED`, `OVER_BUDGET` and `IMPACT_UNRESOLVED` have source-owned next actions. A predicted critical path beyond the ceiling calls for refining required work. Worker count changes preserve the obligation population. Forecasts are empirical; the shared execution deadline limits admitted work when an estimate misses.

## Current observations

A read-only compiler preflight at the [recorded revisions](observations/compiler-preflight.json) found 765 changed inputs, 671 globally scoped inputs and 431 required package checks. The cost forecast remained unavailable and **zero tests executed**. The saved producer source belongs to that observation.

Fresh local cohorts exercised automatic discovery, a later functional source using its costs, implicit input reads, source reservation, cancellation, censored costs and scope preservation. A 400-input/512-package fixture retained all 512 obligations with 2,448 graph edges. These are small implementation observations; forecast reliability across real changes is an ongoing measurement.

The repository CI has a three-minute job ceiling and admitted-work budget, including checkout, setup, compilation and checks. GitHub controls initial queue scheduling. The original run JSON and the work-start timestamp are retained together, including when checks never start. Initial waiting remains visible in the run's total elapsed time and the job summary. This budget does not promise three-minute remote completion including queue and artifact transport. The compiler's complete end-to-end CI budget is still being developed.

## Research connections

[Bazel reverse dependency queries](https://bazel.build/query/guide) provide an established way to reason about change consumers. [Predictive Test Selection](https://arxiv.org/abs/1810.05286) studies learning from historical test outcomes. Here, learned costs feed planning while the selected obligation population remains explicit. [Go testing input logging](https://go.dev/src/testing/internal/testdeps/deps.go) supplies read origins. GitHub's [workflow timeout contract](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) defines the remote job boundary.
